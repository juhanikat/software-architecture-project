\section{Guide}

(Remove this at some point) The actual contents of the report depend on the
framework (its purpose and techincal nature), but in general, the report should
cover the following points (not necessarily in this order):
\begin{itemize}
  \item The purpose and the domain (what to use it for?)
  \item overview of the main functional features (what does it do for you?) if
        applicable
  \item A technical overview (what is it?) and what kind of extension
        interface(s) it provides (inheritance, explicit configuration,
        convention over configuration)
  \item The qualities (-ilities) that the framework claims to support (what?)
        and justifications for the claims (how?)
  \item What is it not suited for (any inherent limitations or reported issues)
        - this may be challenging to research if framework documentation does
        not explain limitations; try to find blogs or other more professional
        articles/books discussing the pros and cons (be critical about the
        sources and try to find multiple sources corroborating the claims)
  \item Architectural impact - what aspect of application/system architecture is
        affected by using it and how? Tool support / automation provided (can be
        also from 3rd parties) to help application developers be more productive
\end{itemize}
